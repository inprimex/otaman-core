`security-gates` ci-slow opt-in is now a per-repo decision: `opt-in` is accepted only on a repo's `ci-slow` entry (not a language default), and `resolve_repo_gates` reports `opt_in` True only when that repo opted in. Previously it was derived monotonically from language defaults, so once a default enabled ci-slow no repo could opt out and the resolved flag answered "is this an opt-in layer?" instead of "did this repo opt in?".
