The dispatch lifecycle gate now fails **closed** when a change's `.openspec.yaml` is present but unparseable: `check_dispatch_gate_at` hard-refuses (regardless of enforcement mode) instead of letting an unverifiable stage dispatch. Previously a parse error read as "no gate", so a malformed file could wave dispatch through. `openspec_is_unreadable` exposes the absent-vs-unparseable distinction for other gate consults.
