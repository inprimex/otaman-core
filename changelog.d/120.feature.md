`CriticCost` and `record_critic_cost` now carry an optional `route` field (the resolved route id, or `None` for the backend default when no router is configured) — the telemetry provenance core already owns via `effective_route`. Default `None` keeps every existing record and caller valid with no migration, and keeps "no router configured" distinguishable from an explicit route, which is what the llm-router verification gate measures (llm-router-backend 1.4 "telemetry carries the route").
