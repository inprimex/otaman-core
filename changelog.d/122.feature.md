`verification-gates.yaml` now carries a `roles` table (agent → roles) so the `role-based` policy resolves from configuration alone — the load-bearing fallback for a single-repo proposal by its own owner, where the excluded proposer empties `stakeholder-affected`. A hook whose primary/fallback pairing cannot select a critic for that shape is refused at parse time (naming the pairing), and unknown top-level keys are now refused instead of silently dropped. A selection that cannot run for want of a declared input reports `could_not_evaluate` (the missing input names) on `SelectionResult`, distinct from an evaluated-but-empty no-eligible-critic.
